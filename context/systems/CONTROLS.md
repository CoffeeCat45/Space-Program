### Время и пауза


| Клавиша                                | Действие                         |
| -------------------------------------- | -------------------------------- |
| **P** или **Space**                    | Пауза / снять паузу              |
| **.** (точка; на RU раскладке **Ю**)   | Ускорить время (следующий шаг)   |
| **,** (запятая; на RU раскладке **Б**) | Замедлить время (предыдущий шаг) |


Шаги time scale: **×0.25 → ×0.5 → ×1 → ×5 → ×10 → ×50 → ×100 → ×1000 → ×10000**.  
×10000 — только **побережье** (Kepler rails: дроссель 0, вне атмосферы). Корабль на аналитической орбите, шаги до 120 с. Земля/Луна без rails — на таком варпе возможен небольшой дрейф тел. При смене active primary (SoI) время автоматически сбрасывается на **×1**, пауза снимается. LOD старого тела не уничтожается (hibernate), стримится как в KSP PQS — без freeze на пару секунд.

Высокий варп (**×5+**) — только **побережье**: дроссель 0 (`X`), вне атмосферы. Тогда корабль на Kepler (эллипс **и** гипербола / Ap «бесконечность»), крупные шаги, LOD не сверлится. SAS (prograde/retrograde) работает и без двигателя — на rails крутится отдельно от орбиты. С тягой варп режется. На оверлее **`sim×N`** — число шагов физики за кадр, не множитель «×5» в жёлтой рамке.

### Манёвры


| Клавиша       | Действие                                                                                                          |
| ------------- | ----------------------------------------------------------------------------------------------------------------- |
| **↑**         | +Δv по prograde (шаг `plannedDeltaVStep`, по умолч. 0.25)                                                         |
| **↓**         | +Δv по retrograde                                                                                                 |
| **→**         | +Δv radial out (R+)                                                                                               |
| **←**         | +Δv radial in (R−)                                                                                                |
| **C**         | Задать Δv для круговой орбиты вокруг active primary                                                               |
| **B**         | Auto-burn (автозапуск манёвра)                                                                                    |
| **Enter**     | У узла: если burn start далеко — warp к началу манёвра; если близко — auto-burn. Без узла — немедленный auto-burn |
| **Backspace** | Очистить план / узел манёвра                                                                                      |
| **N**         | Узел на Ap — **временно выкл.** (карта/старт с планеты)                                                           |


Стрелки правят **узел**, если он есть; иначе — **немедленный план** Δv.

### HUD и язык


| Действие               | Результат                                            |
| ---------------------- | ---------------------------------------------------- |
| **H**                  | Показать / скрыть **Details** и полный блок **Keys** |
| Кнопки **RU** / **EN** | Язык HUD (верхняя строка `SimulationHud`)            |

Какие строки видны в боковом списке: **Настройки → Настройки HUD**. Внизу раздел **Настройки разработчика** (DEBUG GRAPHICS BRIDGE). Галочки, графика (включая режим окна, лимит FPS, MSAA, пост-AA), облака и читы — `settings.json` рядом с проектом / `.exe` (не F5 и не чертежи VAB). Лёгкий `ShareBuild/` после экспорта получает тот же HUD (`hiddenFields` / фон), что Editor. Режим окна: оконный / полноэкранный / безрамочный. Ограничение FPS: поле ввода, **0 или больше 400** = без ограничения. **Качество SMAA** — только если выбран SMAA (не разрешение экрана и не FXAA). В самом низу панели: **Экран загрузки ландшафта** (выкл = мир виден сразу; вкл = чёрный экран, пока под ракетой Max LOD, bootstrap/warmup и ~0.75 с тишины; на экране `L n / max` и BOOT/WARM/PAD). Раскладка пока слева списком.

#### Container prefabs + snap + материалы terrier (2026-07-17) ✅

**Зачем:** KSP-like сборка на **ручных** префабах с нодами в Editor (не runtime-spawn нод по bounds).

**Структура container prefab** (пример `restock-engine-terrier-1`):

```
PartRoot (restock-engine-terrier-1)
├── Engine.obj          ← nested prefab instance (имя GO = Engine)
├── EngineCore909.obj
├── Frame_2.obj / Frame_4.obj / Frame_MLI.obj
├── Node_Top            ← AttachmentNodeMarker index=0, layer AttachmentNode, SphereCollider trigger
├── Node_Bottom         ← index=1, rotation 180° X
└── thrustTransform     ← только Engine
```

**Как работает:**
- **Каталог:** `PartCatalog` видит только `Prefabs/Parts/{Command,FuelTank,Engine}/*.prefab` (flat `Prefabs/Parts/restock-*.prefab` скрыты).
- **Snap:** authored-ноды на слое `AttachmentNode`; после placement `RefreshAllPlacedPartAttachmentNodes` восстанавливает слой (ghost не трогает ноды). Snap по trigger overlap + fallback по позициям owned-маркеров; вертикальный стек top↔bottom без сравнения root Y.
- **Материалы:** меню **Apply Materials to Container Prefabs** → `ResolvePilotMeshMaterialKey` определяет сабмеш по имени вложенного OBJ (`Frame_2.obj` → `Frame 2`), не по дочернему `default`. Blender export: `build_mesh_plan` сохраняет split `Frame 2__restock-engine-125-…` (раньше отбрасывались).

**Pilot-детали (3 шт.):** `Command/restock-mk1-pod`, `FuelTank/restock-fueltank-125-1`, `Engine/restock-engine-terrier-1`.

**Проверка:** VAB → pod → tank → tank → engine снизу; HUD `Snapped: True`, terrier — серые Frame + золотая MLI-фольга (не один коричневый атлас на всё).
