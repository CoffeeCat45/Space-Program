# Earth Sandbox Test — изолированный роадмап (метод чистой комнаты)

Мы останавливаем бесконечный рефакторинг живой базы. Единственный способ сохранить рассудок и победить эту систему — **абсолютная изоляция** (метод чистой комнаты).

Создаём в Unity чистую пустую сцену `Earth_Sandbox_Test` и пишем один изолированный скрипт **без** PQS, **без** Quadtree, **без** сложной физики мультиплеера. Задача сводится к уровню школьной геометрии. Как только микро-сценарий заработает идеально — копируем рабочую математику в основную игру.

**Правило:** никакого старого кода на этапах 1–4 — всё пишется с нуля в одном файле (потом перенос в основную базу).

## ЭТАП 2: ТЗ для Cursor — скрипт-тестер `EarthAssetValidator.cs`

**Роль:** Chief Software Architect.

**Задача:** написать **один** изолированный `MonoBehaviour` `EarthAssetValidator.cs` для чистой тестовой сцены, который проверит согласованность `earth_elevation.raw` и `earth_geographic.png` с канонической математикой координат **без** использования старых классов проекта. Всё с чистого листа — калибровка осей.

### Математический закон (священный канон)

- Долгота `lon` от −180° до +180°. Широта `lat` от −90° до +90°.
- `u = (lon + 180.0) / 360.0`
- `v = (lat + 90.0) / 180.0`

**Контрольная точка:** Мыс Канаверал (28.5° N, −80.6° W) → `u ≈ 0.276`, `v ≈ 0.658`.

### Что должен делать скрипт (all-in-one файл)

1. В инспекторе принимает:
   - `Texture2D` — оригинальный `earth_geographic.png`
   - путь к `earth_elevation.raw` (Int16, 86400×43200)
2. Метод `ValidatePoint(double lat, double lon, string name)`.
3. Внутри метода:
   - рассчитать канонические `u` и `v` по формулам выше;
   - сэмплировать цвет:
     ```csharp
     int texX = (int)(u * texture.width);
     int texY = (int)(v * texture.height);
     Color c = texture.GetPixel(texX, texY);
     ```
   - сэмплировать высоту:
     ```csharp
     long offset = ((long)(v * 43200) * 86400 + (long)(u * 86400)) * 2;
     // Int16 через FileStream / BinaryReader
     ```
   - вывести в `Debug.Log`:
     ```
     [Имя] Канон U={u}, V={v}. Физика Высота={высота}м. Визуал Цвет RGB={c}
     ```

### Три точки в `Start()`

| Точка | lat | lon | Ожидание |
|-------|-----|-----|----------|
| Мыс Канаверал | 28.57 | −80.65 | высота > 0 (суша), цвет — зелёно-коричневая Флорида |
| Тибет | 29.97 | 91.11 | высота > 4000 м (горы), цвет — суша Азии |
| Индийский океан | −10.0 | 60.0 | высота < −3000 м, цвет — синий океан |

**Ограничение:** написать **только** этот один чистый скрипт, не трогая другие файлы проекта.

## ЭТАП 3: Анализ сухих цифр в консоли

Запустить тестовую сцену. Смотреть логи трёх точек. **Нет** шейдеров, **нет** `atan2` на мешах, **нет** вращения — только пиксели и байты на диске.

### Если все три точки — MATCH

- Канаверал — суша, Тибет — горы, океан — синий.

**Вывод:** файлы на диске идеальны, канон `u = lon/360 + 0.5` верен. Баг в основной игре сидит в логике 3D-меша (куб-сфера) или UI-карты — **не** в ассетах.

### Если Канаверал — океан, океан — суша

Сразу видно, какой файл зеркалит на диске. Исправить **один раз** в тестовой сцене (flip PNG или пересчёт offset), не трогая основную игру.

## ЭТАП 4: Изолированная визуальная сфера

Когда логи в консоли идеальны — **в том же** `EarthAssetValidator` добавить:

1. Генерацию **одной** простой процедурной сферы (треугольники, **не** куб-сфера), центр `(0, 0, 0)`.
2. При генерации вершин — `Vector3` → lat/lon (Unity-стиль):
   ```csharp
   float lat = Mathf.Asin(pos.y) * Mathf.Rad2Deg;
   float lon = Mathf.Atan2(pos.x, pos.z) * Mathf.Rad2Deg;
   ```
3. `u`, `v` по проверенной формуле → UV вершины.
4. В `Update()` — кубик-маркер на позиции корабля (например Канаверал):
   ```csharp
   Vector3 markerPos = new Vector3(
       Mathf.Cos(lat) * Mathf.Sin(lon),
       Mathf.Sin(lat),
       Mathf.Cos(lat) * Mathf.Cos(lon)
   ) * radius;
   ```
5. Материал URP/Lit + текстура `earth_geographic.png`.

### Критерий успеха

Отъехать камерой: **маркер-кубик стоит на визуальной Флориде** на глобусе → система откалибрована на 100%.

Зафиксирована рабочая цепочка:

`Vector3 → Lat/Lon → UV` и `Lat/Lon → Vector3`

в чистой комнате, без legacy-кода.

## ЭТАП 5: Перенос калибровочной матрицы в основную игру

После того как в `Earth_Sandbox_Test` глобус, высоты и маркер спавна стали единым целым:

> Мы полностью откалибровали математику в тестовой сцене. Вот рабочий микро-код. Теперь перенеси эти формулы расчёта UV и позиций маркеров во **все** шейдеры и CPU-сэмплеры основной игры, удалив любые другие старые формулы. Основная игра обязана принять этот калиброванный стандарт.

### Что переносить (чеклист)

- [ ] `u/v` из lat/lon (единая формула)
- [ ] lat/lon из unit direction (`Asin(y)`, `Atan2(x, z)`)
- [ ] сэмпл GEBCO raw по `(u, v)` без дополнительных flip
- [ ] сэмпл `earth_geographic.png` по `(u, v)` без runtime flip (если этап 3 прошёл без flip)
- [ ] map mode: world radial → UV (или эквивалент из sandbox)
- [ ] flight chunks: object-space UV, согласованный с sandbox-генерацией сферы

### Что **не** делать при переносе

- Не смешивать старые `flipU` / RSS remap / pad-lock хаки с новым каноном без повторного прогона sandbox.
- Не чинить карту и flight по очереди — сначала один канон, потом везде.
